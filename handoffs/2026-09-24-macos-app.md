# macOS app: Flyto2 Runtime.app in a disk image

Owner: claude
Branch: main
Date: 2026-09-24

## What changed

- `scripts/package-macos.sh` builds `Flyto2 Runtime.app` and
  `Flyto2-Runtime-<version>-macos-<arch>.dmg` on the Mac it runs on. The app
  carries Node 24.21.0 (checksum-verified from nodejs.org), the npm package's
  files, production dependencies installed from the lockfile (hoisted) with
  that Node, and cloudflared (Cloudflare signature checked). It drops what a Mac
  never loads: other platforms' node-pty prebuilds, source maps, type
  declarations and the Claude Agent SDK's bundled Claude Code (221 MB). The DMG
  went from 347 MB to 168 MB.
- Signing: every Mach-O file, node with `packaging/macos/node.entitlements`
  (Node's own entitlements minus `get-task-allow`, which notarization rejects),
  then the bundle; notarize + staple app and DMG when `APPLE_*` credentials are
  set; ad-hoc otherwise.
- `packaging/macos/launcher.c` is the app executable: it writes a one-line
  script into `~/Library/Application Support/Flyto2 Runtime` (no quarantine)
  and opens Terminal on it.
- `distribution.json` marks a packaged Runtime (`src/flyto2/distribution.ts`).
  With it: `Flyto2 Runtime.command` uses the bundled Node and skips pnpm/build;
  cloudflared comes from `vendor/`; `service self-update` refuses and points at
  the releases page (and the MCP instructions say so); the Claude subagent runs
  the user's own `claude`.
- New `app` CLI command: refuses to run from the disk image or an
  AppTranslocation path, runs setup on a first launch, the menu afterwards.
- `.github/workflows/macos-app.yml`: builds arm64 (`macos-latest`) and x64
  (`macos-15-intel`), checks the app starts with no Node on PATH, and attaches
  the DMGs to a release only when the build was notarized.

## Why

Users who cannot clone, install pnpm, or get past Gatekeeper need an app, not
a source checkout. `.dmg` + `.app` was chosen over `.pkg` because the existing
Apple credentials (flyto-cloud) are a Developer ID Application certificate; a
`.pkg` needs a Developer ID Installer certificate.

## Verified

On an arm64 Mac, unsigned (ad-hoc) build:
- Script exit 0; native modules load under the bundled v24.21.0; DMG 168 MB;
  `codesign --verify --deep --strict` passes.
- From the copied app with `PATH=/usr/bin:/bin`: `version` prints 1.0.8.
- `app` run from the mounted DMG refuses with the drag-to-Applications message.
- `app` with an empty config directory enters "Flyto2 Runtime setup".
- `open` on the app: the launcher script is written without quarantine,
  Terminal runs it, and the process is the bundled `node` in the app.
- `pnpm lint`, `typecheck`, `test` (0 failures), `build`,
  `test:package-install`, `flyto-index verify . --full-scan --strict`.

## Not verified

- The x64 build, and signing/notarization: flyto-runtime has no Apple secrets
  yet, so neither the CI signed path nor Gatekeeper on another Mac has run.
- The Claude subagent in the packaged app using the user's `claude`.
- Setup through to "Start Runtime" from the app (it installs the launchd agent
  on the real account).
- Windows: no packaged build exists.
